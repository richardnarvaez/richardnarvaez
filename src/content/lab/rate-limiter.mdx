## The problem

Limit each API client to N requests per minute across a fleet of stateless API servers. Rejected requests get a 429 with a `Retry-After` header. The limiter itself must add well under 5 ms to a request.

## Requirements and scale assumed

- 10k clients, 20k requests per second at peak across 20 servers.
- Limits are per client, configurable, and can change without a deploy.
- Slightly over-admitting for a second is acceptable; dropping all traffic when the limiter is down is not.

## Algorithm

<Decision
  title="Token bucket over sliding window log"
  why="A bucket is two numbers per client: tokens and last refill time. A sliding log stores one timestamp per request, which is memory proportional to the limit."
  tradeoff="Bursts up to the bucket size are allowed. That is usually a feature."
/>

Each bucket holds up to `capacity` tokens and refills at `rate` tokens per second. A request takes one token or is rejected.

<Decision
  title="Lua script in Redis, not two round trips"
  why="Refill and take must be atomic or two servers admit the same last token. A script runs on the Redis side in one round trip."
  tradeoff="Logic lives in a Lua string. Keep it under 30 lines and test it in isolation."
/>

<Decision
  title="Local fallback when Redis is unreachable"
  why="Each server keeps an in-memory bucket per client sized at limit divided by the server count. If Redis times out, the local bucket decides. Traffic keeps flowing at roughly the right rate."
  tradeoff="Uneven load balancing makes the fallback inexact. Acceptable for seconds, not for hours: alert on fallback rate."
/>

## The critical path

1. Middleware reads the client id from the API key.
2. It calls the Lua script with `key`, `capacity`, `rate`, `now`.
3. The script computes `tokens = min(capacity, tokens + (now - last) * rate)`, then takes one if available and writes back.
4. Allowed: the request continues. Rejected: 429 with `Retry-After = ceil((1 - tokens) / rate)`.

## What breaks first

- **Hot clients**: one client at 5k rps hammers one Redis key. Shard the bucket into K sub-buckets and pick one by hashing the request id.
- **Clock skew**: servers pass their own `now`. Use Redis `TIME` inside the script instead.
- **Redis latency spikes**: this is why the local fallback exists. Timeout at 2 ms.
